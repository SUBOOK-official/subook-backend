# 수북 어드민 광고 운영 · 개발 및 사용 안내

작성: 2026-09-30. **현재 상태: 운영 DB·Meta 관리 권한·서버 비밀값 연결 및 운영 배포 완료. 인증된 운영 API 검증 통과. 실제 운영 화면은 사용자가 직접 확인하기로 함.**

바로 열기: [메타 광고 운영](https://admin.subook.kr/admin/meta-ads) · [연동 업무 모음](https://admin.subook.kr/admin/integrations)

## 왜 만들었나

운영진은 광고 성과를 수북에서 확인한 다음, 예산이나 소재를 바꾸기 위해 다시 Meta 광고 관리자로 이동해야 했다. 서비스마다 화면과 용어가 달라 사용법을 반복해서 익혀야 했고, 누가 어떤 광고를 바꿨는지 수북 안에서는 확인하기 어려웠다.

사용자는 Meta 광고 운영을 가장 먼저 어드민으로 옮기고, 다른 서비스는 현재 연동된 업무를 기준으로 정리하도록 요청했다. 이에 수북의 일상 광고 운영 화면과 연동 업무 모음을 추가했다. 광고를 바꾸는 목적·금액·대상이 드러나도록 한국어 입력 화면과 변경 전후 확인 단계를 제공한다.

이 기능은 GA 분석 화면과 역할이 다르다. 성과 대시보드는 광고 결과를 판단하는 곳이고, 메타 광고 운영은 그 판단에 따라 광고를 실제로 바꾸는 곳이다. 두 화면을 바로 이동할 수 있도록 연결했다.

## 어드민에서 추가되는 메뉴

- **메타 광고 운영** `/admin/meta-ads`: 광고 조회·변경·소재·초안·이력.
- **연동 업무 모음** `/admin/integrations`: 광고, GA·주문 성과, CJ 수거, 주문·배송·환불, 알림톡·문자, 사진 가공의 기존 업무 화면을 찾아가는 안내.
- 기존 **성과 대시보드**의 광고 관리 링크를 수북의 광고 운영 화면으로 연결.

연동 업무 모음은 이미 있는 기능의 위치를 정리한 것이다. CJ·결제·알림 기능을 이번에 새로 개발했다고 설명하면 안 된다. 실제 연결 상태는 각각의 업무 화면에서 확인한다.

| 변경 이력 | 변경한 관리자·시각·변경 전후·처리 결과 조회 | 최근 100건. Meta 밖에서 직접 수정한 작업은 기록되지 않음 |

Meta의 모든 기능을 복제한 상태는 아니다. 캐러셀·동적 카탈로그 소재·새 맞춤/유사 타겟 생성·고급 입찰·자동 규칙·A/B 실험·18세 미만 대상 설정·여러 광고 계정 전환은 이번 구현 범위에 없다. 사업자/계정 인증·결제수단 변경·정책 이의신청도 기존 Meta 절차를 사용한다. 이것은 이번 구현의 범위이며, 모든 항목이 API로 불가능하다는 뜻은 아니다.

## 사용 방법: 매일 광고를 확인하고 조정하기

1. 어드민의 **메타 광고 운영**을 연다.
2. 상단에서 계정 이름과 연결 상태를 확인한다. **조회 전용**이면 외부 광고를 바꾸는 버튼이 잠겨 있다.
3. 성과 기간을 선택한다. 상단 숫자는 계정 전체, 각 행의 숫자는 해당 광고 묶음의 결과다.
4. 캠페인 이름을 누르면 그 안의 광고세트, 광고세트 이름을 누르면 그 안의 광고를 본다.
5. 예산을 바꾸려면 해당 행의 **수정**을 누르고 금액을 원 단위로 입력한다. 예를 들어 `30000`은 3만원이다.
6. **반영 전 내용 확인**을 누르면 이전 금액과 새 금액이 나온다. 대상과 기간도 함께 읽는다.
7. 확인란을 선택한 뒤 **반영**을 누른다. 완료 표시를 확인한다.

일일 예산은 하루 평균 기준이다. 일별 실제 지출을 고정하는 장치는 아니다. 예산 입력 한도는 시스템 입력 검증이며 회사의 지출 승인 한도를 대신하지 않는다.

계정 전체 합계와 선택한 광고세트의 합계는 범위가 다르다. 구매 수는 Meta가 광고 성과로 인정한 구매다. 실제 결제가 완료된 매출은 **매출·GA 함께 보기**에서 주문 DB 수치를 확인한다. Meta 수치는 최대 15분 캐시하며 광고 플랫폼 자체의 처리 지연도 있을 수 있다.

## 사용 방법: 처음부터 광고 만들기

광고 구조는 세 단계다.

- **캠페인**: 무엇을 위한 광고인지 정한다. 예: 교재 구매 늘리기.
- **광고세트**: 누구에게, 언제, 어느 예산으로 보여줄지 정한다.
- **광고**: 실제 고객이 볼 문구와 이미지·영상을 선택한다.

먼저 캠페인을 만들고, 캠페인 이름을 눌러 광고세트를 만든다. 구매 목표라면 계정에 연결된 구매 픽셀을 선택한다. 캠페인 예산을 사용하면 광고세트에서 예산을 다시 입력하지 않는다.

이미지는 **이미지·영상 → 이미지 업로드**로 등록한다. 이어서 **소재 → 만들기**에서 페이지, Instagram 계정, 이미지 또는 영상을 선택하고 본문·제목·버튼·수북 도착 주소를 입력한다. 영상은 기존 Meta 영상 또는 공개 MP4 주소 등록을 사용한다. 신규 영상의 인코딩이 끝나기 전에는 소재 생성이 거절될 수 있다.

광고 출처 이름표 예시:

| 항목 | 예시 | 뜻 |
| --- | --- | --- |
| 출처 | `instagram` | 고객이 어떤 서비스에서 왔는지 |
| 매체 | `cpc` | 유료 광고 유입임을 구분 |
| 캠페인 이름 | `202610_sales_math` | 운영자가 알아볼 수 있는 캠페인명 |
| 실제 캠페인 ID | 캠페인 목록의 숫자 ID | 광고 계정의 실제 캠페인과 연결 |
| 소재 구분명 | `feed_image_a` | 어떤 문구·이미지에서 왔는지 |

그 다음 광고세트 안에서 **광고 만들기**를 누르고 준비한 소재를 선택한다. 생성 후 광고는 꺼진 상태다. 미리보기·대상·예산을 검토한 다음 켠다. 캠페인·광고세트·광고의 상위 설정이 꺼져 있으면 해당 광고는 게재되지 않는다. 켜짐 요청이 성공하더라도 심사·계정 제한·일정 때문에 즉시 게재되지 않을 수 있다.

## 초안·협업·오류 처리

- **수북 초안 저장**은 내부 메모다. 저장만으로 광고가 생성되거나 광고비가 발생하지 않는다.
- **Meta 반영**은 실제 광고 계정에 변경을 요청한다. 초안 저장과 다르다.
- 검토는 10분 동안 유효하다. 그 사이 광고가 바뀌었으면 새로고침 후 다시 검토한다.
- 다른 운영진이 먼저 초안을 수정하면 덮어쓰지 않고 충돌을 안내한다.
- 변경 이력에 **반영 완료**가 나오면 요청이 성공했다는 뜻이다. 게재·심사 통과와 같은 뜻은 아니다.
- **처리 중** 또는 **결과 확인 필요**면 같은 작업을 반복하지 않는다. 광고 목록에서 현재 상태를 먼저 조회하고 작업 식별번호로 담당자에게 확인을 요청한다.
- 여러 건을 바꾸다가 한 건이 실패하면 나머지는 실행하지 않는다. 앞서 성공한 항목이 자동으로 원복되지는 않는다.

## 운영 연결과 검증

운영 Vercel에는 기존 `META_ADS_ACCESS_TOKEN` 조회 토큰과 새 `META_ADS_MANAGEMENT_TOKEN` 관리 토큰이 별도로 저장돼 있다. 둘 다 서버 비밀값으로 보호하며 브라우저에 전달하지 않는다. 기존 GA·Meta 성과 조회 연결은 유지한다.

연결 대상은 기존 수북 광고 계정 `1507168001446517`이다. 필요한 것은 이 계정의 광고 운영 권한과 사용할 페이지·Instagram·픽셀 등 자산의 이용 권한이다. 최소 `ads_management`가 필요하며, 앱·자산별 추가 권한은 공식 콘솔과 실제 응답으로 확인한다. `business_management` 등 광범위한 권한을 자동으로 추가하지 않는다.

- 사용자 승인과 Meta 이메일 본인 인증 후 전용 Employee 시스템 사용자 `Subookmanager`를 연결했다. 기존 `SubookReader`·CAPI 계정은 유지했다.
- 광고 계정은 캠페인 관리, 페이지·Instagram은 광고·인사이트, `subook 데이터`는 이벤트 데이터 사용, 앱은 테스트 권한을 부여했다. 결제수단·계정 권한 관리 권한은 부여하지 않았다.
- 발급 범위는 `ads_management`, `ads_read`, `pages_read_engagement`, `pages_show_list`이다. 토큰은 Vercel production의 Secret으로 저장했다.
- migration `20260930092122_admin_external_operations.sql` 운영 적용과 원격 이력 일치를 확인했다. 익명 접근은 401로 차단됐다. 기존 미추적 결제 migration은 제외했다.
- 실제 Meta API에서 계정·관리 권한, 캠페인 3개·광고세트 5개·광고 27개, 소재·페이지·픽셀·이미지·영상 조회를 확인했다. 이 개수는 2026-09-30 확인 시점 기준이다.
- `subook.official` Instagram은 기존에 페이지에만 연결돼 있었다. 수북 광고 계정에 연결한 뒤 API에서 해당 Instagram 계정이 소재 선택 목록에 나오는 것을 확인했다.
- 배포는 frontend/backend 별도 commit/push 후 루트 `npm run deploy:admin`으로 진행한다. 실제 광고 생성·활성화·예산 변경은 검증 목적으로 실행하지 않았다. 변경 실행 흐름은 모의 Meta 응답을 사용한 API·브라우저 검증으로 확인했다.
- 배포 `dpl_6Vq8yiqG3qgcV1KASZ3iFw6WJ6G8`의 `READY`·`production` 상태와 `admin.subook.kr` 반영을 확인했다. 구현 커밋: frontend `7839081`, backend `153cfea`.
- 운영 관리자 인증을 거친 연결·전체 목록·모든 자산·초안·이력 조회가 200, 관리 권한 `canManage: true`였다. 캠페인→광고세트→광고 하위 조회와 광고 상세·미리보기 200, Meta 성과 `ready`를 확인했다. 검증용 인증 세션은 종료했다.
- 로컬 브라우저 동작은 모의 데이터로 검증했다. 운영 브라우저는 로그인 전 화면까지만 확인했으며, 사용자가 운영 화면 확인을 직접 하기로 했다. 운영 광고 변경 요청의 실제 실행 성공까지 검증했다고 설명하지 않는다.

## 개발자 참고

- API: `api/admin/meta-ads.js`, 서버 도메인 로직: `api/_lib/metaAds.js`, 내부 초안·이력: `api/_lib/adminExternalStore.js`.
- 권한: Supabase 사용자 검증 + `is_admin_user`, 외부 변경 시 현재 `ads_management`·계정 user_tasks 재확인. 토큰은 서버에서만 사용.
- 계정 격리: 고정 계정의 객체 소유권 및 선택 자산 목록 검사. 임의 Graph 경로·파라미터·다른 광고 계정 사용 차단.
- 실행: prepare → 사용자 검토 → execute. SHA256 요청 해시, 객체 버전 재조회, DB의 원자적 실행 선점, 동일 객체 동시 실행 제한.
- GET은 timeout과 일시 오류 재시도. POST는 한 번만 전송하고, 결과가 불명확하면 unknown 상태로 남겨 자동 재시도를 금지.
- service role 전용 테이블 2개, RLS 활성화, anon/authenticated 권한 없음. 완료·만료된 준비 내용에서 이미지 원문 payload를 제거. 만료 정리는 다음 준비 요청에서 수행.
- rollback: 관리자 앱을 이전 배포로 되돌린다. 변경 이력 테이블은 보존한다. Meta에 이미 반영한 변경이 자동 취소되는 것은 아니다.
- 검증: Node API/검증·PGlite RLS/동시성 테스트, frontend lint, 변경 admin 파일 lint, admin/public build, public 회귀 테스트 266건, 브라우저 로컬 모의 데이터로 예산 변경·초안·조회 전용·이력·메뉴 이동 확인. 실제 광고 변경 호출은 하지 않음.
