# 박스 수 변경과 정산 반영

2026-11-02 사용자 승인 범위: `shipments.box_count` 저장 시 미지급 재계산과 기지급 차액의 추가 지급 대기 생성. 별도 상품화 비용 입력/CS 할인 필드는 추가하지 않는다.

- `admin_update_shipment_box_count`는 이전 박스 수를 비교하고 수거 행을 잠근다. 트리거가 직접 UPDATE 경로에도 동일 계산을 적용한다.
- 기존 pending/approved 정산은 생성 순서로 차감액을 재배분한다. 음수 지급액을 만들지 않고 잔액은 다음 판매에 이월한다.
- completed 원장과 기존 이체 기록은 변경하지 않는다. 반환액은 RLS가 적용된 `settlement_box_cost_adjustments`에 기록한다. 수거별 pending은 한 건만 허용하며 박스 수를 다시 늘리면 이 pending을 조정/취소한다.
- 누적 차감은 반환 대기·완료분을 뺀 금액이다. 재계산 시 고정분 = 누적 차감 − 기존 미지급 차감 + 기존 반환 대기. 이미 지급한 반환액은 다시 생성되지 않는다.
- 새 원장은 기존 정산 ID sequence를 함께 사용한다. 조회 전용 내부 view가 기존 정산과 합쳐 관리자/회원 조회·리마인더를 제공한다. 별도 매출을 만들지 않으며 비용 반환은 음수 차감으로 표시한다.
- 완료는 `admin_complete_settlement_payouts`로 처리한다. 수거→정산 순서로 잠그고 화면에서 확인한 행별 금액/미지급 상태를 검증한다. 기존 일반 정산 RPC를 내부 호출하고 추가 지급도 같은 트랜잭션에서 완료한다. 예전 지급 RPC의 authenticated 직접 실행 권한은 회수한다.
- 원주문의 미해소 환불·회수 건은 비용 변경과 추가 지급을 보류한다. 실제 은행 송금은 수행하지 않는다. 송금 후 완료 버튼으로 기존 셀러 묶음 알림을 발송한다.
- 배포 자체는 기존 수거/정산 값을 백필하지 않는다. 김정환 고객의 별도 정정·추가 송금 확인 이력은 중복 처리하지 않는다.

검증: `node backend/scripts/test-box-cost-reconciliation.mjs` (루트에서 실행). 격리 PostgreSQL에서 미지급·기지급·혼합·반복 변경·증액·이월·중복 완료·환불 보류·본인 조회·RLS를 검증한다.

롤백은 박스 수 변경과 새 지급 진입을 잠시 중단하고 이전 앱/RPC 접근을 복원하는 순서로 진행한다. 새 지급 원장을 삭제하거나 기존 completed 금액에 합쳐 덮어쓰지 않는다. 운영 적용 전 가져온 RPC 원본은 `.codex/box-cost-reconciliation/`에 보존한다.
