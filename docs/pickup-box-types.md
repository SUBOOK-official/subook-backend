# 수거 박스별 CJ 규격

2026-09-18부터 고객이 신청서에서 각 박스의 규격을 직접 선택한다. 규격별로 크기와 무게를 모두 만족해야 하며, 둘이 다른 단계이면 더 큰 단계를 선택한다.

| 선택 | 세 변 합 | 무게 | BOX_TYPE_CD |
| --- | --- | --- | --- |
| 극소 | 80cm 이하 | 2kg 이하 | 01 |
| 소 | 100cm 이하 | 5kg 이하 | 02 |
| 중 | 120cm 이하 | 10kg 이하 | 03 |
| 대1 | 140cm 이하 | 15kg 이하 | 04 |
| 대2 | 160cm 이하 | 20kg 이하 | 07 |

- 코드·수치 출처: CJ 제공 `docs/cj/CJLAPI-DeveloperGuide-V3.9.4.txt` §1.2.4.
- [CJ 공식 개인택배예약 안내](https://www.cjlogistics.com/ko/tool/parcel/reservation-general): 세 변 합 최대 160cm, 최장변 100cm, 서적 20kg 이내, 크기와 중량 중 큰 값 적용. 2026-09-18 확인.
- 서적 수거에서는 이형(05)·취급제한(06)을 제공하지 않는다. 20kg을 넘으면 분할 포장한다. 권수로 무게를 추정하지 않는다.
- 요청당 최대 5박스는 기존 수북 CJ 접수 상한에 맞춘 서비스 제한이다. CJ 공식 규격의 일부가 아니다.
- 상품화 비용(박스당 5,000원), 수수료·정산 로직은 이번 변경에 포함되지 않는다. 실제 CJ 운임은 계약 규격별로 적용된다.

## 저장·접수·재접수

- `pickup_requests.box_type_codes`는 박스 순서대로 코드 배열을 저장한다. 신규 신청은 v3 RPC에서 필수 검증하며, 구형 신청서의 누락 제출도 INSERT 트리거에서 거부한다. v2를 호출해 기존 OTP·차단·계좌 자동등록·수수료 동의 검증을 보존한다.
- 기존 신청의 NULL은 미확인이다. 소급으로 극소를 채우지 않는다. 운영자가 미접수 건의 ‘박스 규격 설정’에서 확인·저장한 후 CJ 접수한다.
- 이미 접수된 건의 규격 수정은 ‘CJ 재접수’에서만 한다. 새 규격을 검증한 뒤 기존 예약 전량 취소 → 새 규격 저장 → 새 송장 발급 순서다. 취소 실패 시 중단한다.
- CJ 접수는 각 박스의 저장 코드로 `BOX_TYPE_CD`를 구성한다. `CJ_BOX_TYPE_CD` 환경 변수로 수거 규격을 덮어쓰지 않는다. `box_waybills[].box_type_cd`와 접수 이벤트에도 실제 전송 규격을 남긴다.
- 일부 접수 실패 후 재시도는 미접수 박스만 처리한다. 기존 송장·추적·취소 기록과 박스별 고객사용번호를 보존한다.
- 구매 주문 출고(`cj-delivery`)와 구매 반품(`cj-return`)은 이번 판매자 수거 변경 범위 밖이다.

## 검증

`node scripts/test-pickup-box-types.mjs`는 격리 PostgreSQL에서 새 migration, 레거시 NULL 보존, 규격 제약, 구형 제출 거부, RPC 권한, 목록·수정 가드를 검사한다.

`node --test tests/pickup-box-types.test.js`는 외부 통신을 모의 처리하여 규격별 CJ payload, 멀티박스 부분 실패·재시도, 재접수 취소 실패 보호와 운영 API 미러 일치를 검사한다. 실서비스 수거 예약을 테스트로 생성하지 않는다.
