# 수거 수수료 정책 개정 (2026-09-10)

사용자 요청: 배포 이후 새로 맡기는 수거 건에만 수수료를 인상한다. 기존 접수·수거 건에 소급하지 않는다.

| 판매가 | 인상 전 정책 | 신규 정책 (`2026-09`) |
| --- | --- | --- |
| 1만원 미만 | 45% | 50% |
| 1만원 이상 | 40% | 45% |

2026-02-03 전 수거의 35%/30%도 유지한다. 정확히 1만원은 기존 서버의 `price < 10000` 경계를 유지하여 45%다. 오래된 안내문의 '초과/이하'는 실제 계산과 일치하도록 '이상/미만'으로 교정했다.

## 적용 기준

- `pickup_fee_policy_releases.activated_at`이 실제 배포 완료 후 정책 활성화 시각이다.
- 기존 `pickup_requests`와 `shipments`의 `fee_policy_version`은 NULL인 채 유지한다. 기존 행을 백필하거나 정산액을 재계산하지 않는다.
- 온라인 신청: 활성화 이후 신규 약관에 동의하고 접수한 건에만 `2026-09`를 저장한다. 배포 전에 열어 둔 이전 신청서는 서버가 새로고침·새 약관 확인을 요구한다.
- 신청에서 검수 건 생성: 해당 신청(병합 시 원본)의 정책을 승계한다. 희망 수거일·입고일·판매일·구매확정일로 신규 요율을 판단하지 않는다.
- 직접 등록: 운영자가 '인상 후 신규 접수' 또는 '인상 전 접수'를 선택한다. 인상 전 수거일에 신규 정책을 선택하면 거부한다. 이전 클라이언트나 정책 미확인 직접 등록은 기존 요율로 보수적으로 처리한다.
- 같은 회원의 재신청도 별개의 수거 건이다. 기존 수거는 기존 요율, 시행 후 새로 맡긴 수거는 신규 요율이다.
- 정책 스냅샷 변경과 다른 정책끼리의 신청 병합·입고 연결은 차단한다.

## 정산과 조회

`calculate_settlement_fee_percent(integer,date,text)`가 정책을 해석한다. 2인자 기존 함수는 그대로 유지한다. 자동·수동 정산은 수거 건의 스냅샷을 3번째 인자로 넘긴다. 기존 정산의 차감·반올림·박스비·부분환불·비회원·중복지급 방지 동작은 유지한다.

관리자 미리보기와 레거시 셀러 조회는 `shared-domain/settlement.js`의 같은 정책을 사용한다. 공개 판매 안내·신청서·약관·FAQ도 함께 갱신한다.

## 배포와 검증

1. 테스트·lint·세 앱 build가 통과한 후 준비 migration `20260910054749_pickup_fee_policy_versions`를 적용한다. 이 단계에서는 신규 요율이 활성화되지 않는다.
2. 루트 `npm run deploy:admin`, `npm run deploy:seller`, `npm run deploy:public`로 배포하고 production READY를 확인한다.
3. 별도 활성화 migration에서 `pickup_fee_policy_releases`에 `2026-09`를 INSERT한다. 활성화 시각은 DB에 기록된다.
4. FAQ와 실제 정책 시각을 확인하고 기존 수거 정책·정산액 보존을 검증한다.

회귀 테스트: `supabase/tests/pickup_fee_policy.sql`을 테이블 구조만 복사한 격리 스키마에서 실행하고 전부 ROLLBACK한다. 운영 알림 트리거는 복사하지 않는다. 지연 입고·이전 신청서·정책 변경 차단·직접 등록·가격 경계·자동/수동 정산·박스비·환불·중복지급 방지를 확인한다.

롤백: 활성화 전에는 프런트를 되돌릴 수 있다. 활성화 후에는 이미 동의한 정책 스냅샷을 유지하고 후속 migration으로 수정한다. 활성화 행이나 스냅샷을 삭제하여 기존 수거를 재판정하지 않는다.

공식 적용 절차: [Supabase CLI](https://supabase.com/docs/reference/cli/installing), [Vercel 배포](https://vercel.com/docs/deployments).
